# dsh-setting-backup

把 DeepSeek Harness 的**配置**和**已安装插件清单（含精确版本）**打成一个 zip。换机器、重装系统、或者把调好的工作台复制给同事时，一次导入就能还原。

装好后在 DSH 左侧栏有「配置备份」入口，主区和 设置 → 配置备份 打开的是同一个页面。

## 它解决什么

换一台电脑时，配置文件本身好办，真正难的是「这边装了哪些插件、各是什么版本、从哪装的」。少装一个，或者版本对不上，界面就变样、功能就失效。

这个插件把两样东西一起打包，并按固定流程还原：

```
导入 zip  →  重启①  →  自动安装插件  →  重启②  →  原工作台回来
```

## 安装

远端安装：

```bash
dsh plugin --profile desktop add https://github.com/<you>/dsh-setting-backup
```

本地开发或离线安装：

```bash
dsh plugin --profile desktop add "D:/code/dsh-plugins/dsh-setting-backup"
```

装完重启 DSH 即可。

> 本插件自己是还原的载体。全新环境里没有它，就没有导入界面——所以换机器时请先把它装上，或在导出时勾选「同时包含本插件包」。

## 导出

1. 打开「配置备份」页面，在「导出」区点「导出 zip」。
2. 产物默认落在 DSH_HOME 下（不放 profile 里，避免 profile 重建时被清掉）：

```
~/.dsh/setting-backup/exports/dsh-setting-backup-<yyyy-MM-dd_HH-mm-ss>.zip
```

时间一律用本地时间，界面显示为 `yyyy-MM-dd HH:mm:ss`。

3. 想存到别处就点「另存为…」：

- 浏览器支持原生保存对话框时，直接弹窗选目录和文件名；
- 不支持时退回普通下载流程，同样能选位置。

两种情况都会在上面那个 `exports` 目录里**再留一份默认副本**，当作安全网。

**凭据默认不导出。** 只有勾选「包含凭据」才会写入，包内会被标记为敏感，导入时必须再确认一次。

不包含 `sessions`、`attachments`、`cache`、`node_modules` 和业务数据库——那些是数据，不是配置。

## 导入与还原

1. **导入**：选 zip，先看预检——要装几个插件、几个版本不符、哪些是本地来源。确认后插件会：
   - 给当前配置存一份本地快照（随时可回退）
   - 解包到暂存区
   - 只立刻覆盖 `settings.yaml`
   - 插件相关配置一概不动
   - 状态置为「待安装」，提示你重启①
2. **重启①**：进入安装环节，逐个执行 `dsh plugin add <name>@<version>`，页面上逐条显示结果。
3. **装齐后提交配置**：这一步才会写插件配置与插件列表。写入前会逐条确认每个包真的装上了，有一条不满足就整体拒绝并报出包名——不会留下一个起不来的 DSH。
4. **重启②**：配置生效，回到原来的工作台。

为什么非要重启两次：DSH 启动时会校验插件列表里的每个包，缺一个就拒绝启动。要是导入时就把还没装的插件写进去，重启后 DSH 根本起不来，安装环节也没机会执行。分两段走，才能保证任何一步失败时 DSH 都还能正常打开。

## 失败与回退

- 单条插件安装失败不会中断其余条目，但状态会停在「失败」，不进入提交环节。
- 页面「故障与日志」区会列出失败项和错误摘要。
- 「重试安装」再试一次；「整单回退」把配置恢复到导入前的状态（纯本地文件操作，不依赖网络）。

## 已知边界

- `link:`、`file:`、GitHub 直连来源的插件，换台机器不一定还能重新下载。预检会单独列出来，请你手工处理，不会假装装成功。
- 插件版本按导出那一刻的实装版本精确还原，不跟随升级。
- 本插件只能还原 DSH 自己的配置和插件，不负责恢复你的会话、附件和业务数据。
